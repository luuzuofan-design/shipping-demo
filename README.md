# 每日生产计划与订单流程

在线演示：[订单全流程 Demo](https://luuzuofan-design.github.io/shipping-demo/)

以当天各型号需要完成打包的数量为计划目标，记录生产过程中的领料、补料与异常，日终按实际打包数逐型号核对。订单从需求到回款的完整流程保留为参考。全部使用虚拟数据，原网址保持不变。

## 覆盖范围

1. 需求沟通：产品、数量、定制要求与生产评估交接。
2. 库存交期：核对库存和物料，选择无需采购或需采购分支。
3. 合同采购：确认交期与合同、采购安排和到货跟踪。
4. 排产领料：生产通知、每日任务、领料与随工记录。
5. 生产质检：拨杆保压与底座装配、延迟组件装配与检测两条并行支线，汇合后合装、拉力测试与成品抽检。
6. 包装贴标：模拟罩壳扫码、保存产品码、同一原码再次扫码和彩盒贴标。
7. 发货交接：客户通知、两种运输方式、地址及入库要求。
8. 开票回款：开票与到账均确认后，才能演示订单完结。

定义了 19 个业务节点。运输方式择一；采购节点按物料判断启用，页面显示当前路径的交接进度。

每个节点展示接手岗位、输入、操作、输出、下一位接手人和待现场确认的问题。完成、撤销与质检异常会更新相关后续状态，保留独立并行支线的记录。

## 全流程参考场景

- 从接单开始：逐阶段查看完整流程。
- 看并行生产：观察装配支线与合装的依赖关系。
- 看质检异常：观察成品异常如何影响包装和发货。
- 试发货缺地址：填写虚拟地址，或切换客户叫车。
- 看开票回款：体验已开票但未到账不能完结。
- 生成全流程摘要：汇总各阶段状态和待确认事项。

## 每日生产计划

首页以当天各型号应完成打包的件数为目标，同一计划可包含多个型号及规格，并可关联订单和备注。确认后，从领料开始推进 A/B 并行生产、汇合、检验及包装交接。

- 现场可集中记录领料、补料、不可用物料、异常及处理说明。物料按自己的名称、数量和单位记录，不自动换算成品数量，不自动判报废。
- 每个型号按工序推进：领料核对；A 线保压与底座装配；B 线延迟轴、开关装配、逐件检测及批次抽检；汇合后的合装、拉力测试和成品抽检；最后包装贴标。可由现有负责核对的人集中确认，无需每个工人频繁操作网页。
- 支线完成进度由各工序汇总，不能手动把整线直接标为完成。前置未完成时不能确认后续；两条支线都完成后才可合装，检验工序需明确合格结论，最后确认包装完成后才能登记正数打包量。
- 日终逐型号核对实际完成打包数，允许多于、少于计划或为零。未核对与实际为零明确区分。有差异时填写原因，并可说明未打包在制品及待处理情况。
- 工序未走完时，可登记当日实际未打包的 0 件及在制情况，不能跳过工序登记正数打包。异常或重开工序保留原记录，关联后续标为待复核，独立支线保留；原打包数不删除，但需在工序复核后重新核对。
- 只有每个型号均核对且达到自己的计划，才显示当日计划完成。甲超 10、乙差 10，即使总件数相同，仍显示未全部完成。
- 计划调整保留原目标、调整人和原因；日终核对后锁定该型号计划基准。更正实际打包数需说明原因并保留原核对记录。
- 按日期独立保存计划，刷新后保留，可导出本日结果、过程记录和核对历史。当前仅保存在本机浏览器，不与其他设备同步。

旧版整线状态和历史打包数升级时保留，逐工序状态不自动补齐。原有正数打包记录显示待工序与数量复核；第一次保存升级记录时，会在当前浏览器另存一份旧版本地备份。操作历史默认收起，与当前工序状态分开展示。

「看日终差异示例」使用型号甲计划 100、实际打包 110，型号乙计划 80、实际打包 70 的虚拟例子。已有计划的日期不会被示例覆盖。旧的报数入口已移除，原来的 `#cart` 链接会打开每日计划。之前试填的旧数据不自动转换为计划或打包数。

## 运行与发布

直接打开 `index.html` 即可使用，无需依赖或构建。GitHub Pages 从 `main` 分支 `/ (root)` 发布。

订单全流程参考的交接状态仅在当前内存中模拟，刷新后恢复示例；每日计划和记录单独保存在当前浏览器的本地存储。两者不自动互相放行。页面不连接企业系统，不执行真实签约、采购、检验、打印、运输、开票或收付款，不使用外部脚本或统计工具，不向服务端上传试填记录。正式多人处理实单仍需共享存储、身份确认与现场规则。

原始内部表格、公司和人员姓名、真实客户信息、承运方及内部结算约定不在公开仓库中。技术标准、异常处理和尚未确认的职责标为待确认。前置关系用于交接演示，不替代正式生产放行规则。
